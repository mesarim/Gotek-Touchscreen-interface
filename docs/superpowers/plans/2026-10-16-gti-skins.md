# GTi skins Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A user can download a NEO starter skin, edit its PNG, upload it as one `.gts` file in the web panel, and see it live on the JC3248; every existing theme and `CONFIG.TXT` keeps working.

**Architecture:** A header-only, host-testable core (`skin_gts.h` container, `skin_draw.h` slot table + 9-slice + blend) shared by firmware and tests. The JC3248 sketch loads the atlas into PSRAM and draws slots through new `skin*` helpers hooked in beside the NEO helpers. `web_panel.h` gets chunked skin endpoints; `webui.html` gets the packing, validation, starter rendering and import/export in JS (one renderer, offline).

**Tech Stack:** Arduino-ESP32 core 3.3.12, PNGdec 1.1.6, `WebServer` in `web_panel.h`, plain JS in `webui.html`, g++ host tests (pattern of `tools/test_cracktro_gti.sh` on branch `cracktro-gti`).

**Spec:** `docs/superpowers/specs/2026-10-16-gti-skins-design.md` (and `2026-10-07-gti-theme-section-design.md`, which this builds on).

## Global Constraints

- Skin file: magic `GTS1`, max file 262144 bytes, name `A-Z 0-9 _` max 16, stored at `/GTI/THEMES/<NAME>.gts`; `.gts` wins over `<NAME>.json` of the same name.
- One skin for all screens: no screen-class field (header byte is reserved `0`); backgrounds per size/orientation, `BG_TILE` fallback, then the colour theme's background.
- Picking a skin sets `THEME=<name>` and NEO off; slots a skin lacks are drawn the classic way (`BUTTONS=` pill/flat + colour theme), never the NEO way. The 8-entry custom cap is shared by colour themes and skins.
- State markers (green/amber/red edges, `> <`) are drawn over skin art; labels use the manifest `text` colour; no new manifest fields.
- Alpha is real PNG alpha with blending. Icons are 16x16 on the grid, scaled by whole numbers (`ICONS_2X` used when present).
- Skin listing never decodes an atlas; only the active skin's atlas and the one matching background are decoded.
- JC3248 only in this plan. Build into a scratch `--output-dir`, `--jobs 3`, detached, watch the log; committed `build/` binaries are not replaced.
- Commit messages and PR text carry no AI attribution (no `Co-Authored-By`, no "Generated with" footer): the user's global rule overrides any harness reminder.
- `webui.html` changes are additive so the file stays identical in the OMEGAWARE tree.

## Review Focus

1. A `.gts` with lying, truncated or overflowing length fields (must be rejected before any read past the buffer) → Task 1.
2. Activating a skin when PSRAM is short (must refuse, keep the previous look, no crash, one log line) → Task 3.
3. An upload interrupted halfway, or chunks replayed or out of order (the partial file must never appear as a skin) → Task 6.
4. All four screen rotations (`g_rot` 0..3) draw the same skin picture → Task 4.
5. Unsafe or colliding names (`../X`, lower case, 17 characters, `X.json` plus `X.gts`) → Tasks 5 and 6.

## File Structure

- Create `firmware/shared/skin_gts.h` - container parse/pack/validate, background ids (no Arduino includes).
- Create `firmware/shared/skin_draw.h` - slot table, `slice9`, `blend565`, `drawSlice` template, icon scale (no Arduino includes).
- Create `tools/test_skin_gts.cpp`, `tools/test_skin_draw.cpp`, `tools/test_skin.sh`, `tools/gts_fixture.js` - host tests and the JS/C cross-check.
- Modify `firmware/Gotek_JC3248/Gotek_JC3248.ino` - loader, draw hooks, list/config integration, hooks for the panel, `FW_VERSION`.
- Modify `firmware/shared/web_panel.h` - skin endpoints, `has_skins` in `/api/system/info`.
- Modify `firmware/shared/webui.html` (then regenerate `webui.h` with `firmware/shared/make_webui_header.py`) - skin card in the Theme Editor.
- Create `docs/skins/README.md` and `docs/skins/slot-map.png` - slot reference and labelled overlay.

### Task 2: Slot table, 9-slice, blend

**Files:** Create `firmware/shared/skin_draw.h`, `tools/test_skin_draw.cpp`.

**Interfaces:**
- Consumes: nothing from Task 1.
- Produces (namespace `skin`): `enum SlotId:uint8_t{S_KEY_UP,S_KEY_DOWN,S_PANEL,S_ROW_SEL,S_TILE,S_ICONS,S_ICONS_2X,S_COUNT};` `struct Slot{uint16_t x,y,w,h;uint8_t border;};` `constexpr Slot SLOTS[S_COUNT]` with the atlas fixed at **256x192** (`ATLAS_W=256`, `ATLAS_H=192`, `SLOT_VER=1`):
  KEY_UP (0,0,48,48,b10), KEY_DOWN (48,0,48,48,10), PANEL (96,0,48,48,10), ROW_SEL (144,0,48,32,8), TILE (0,64,64,64,0), ICONS (64,64,128,32,0; 8x2 cells of 16), ICONS_2X (0,128,256,64,0; 8x2 cells of 32). Icon cell order (row-major, first 8 named, rest reserved): INSERT, EJECT, FOLDER, STAR, GEAR, BATTERY, WIFI, SEARCH. *(Plan's call; rectangles are the contract and may only change with `SLOT_VER`.)*
  `struct Piece{int16_t sx,sy,sw,sh,dx,dy,dw,dh;};` `int slice9(const Slot&s,int dw,int dh,Piece out[9]);` (count of non-empty pieces; if `dw<2*border` or `dh<2*border` the border shrinks to `min(dw,dh)/2`; pieces tile the destination exactly)
  `uint16_t blend565(uint16_t src,uint8_t a,uint16_t dst);` (a=0 → dst, a=255 → src, exact; RGB565 host order, not byte-swapped)
  `int iconScale(int screenW,int screenH);` (2 when `max(w,h)>=800`, else 1)
  `struct Atlas{uint16_t w=0,h=0;uint16_t*rgb=nullptr;uint8_t*a=nullptr;};`
  `template<class Put> void drawSlice(const Atlas&,const Slot&,int dx,int dy,int dw,int dh,Put put);` calls `put(int x,int y,uint16_t rgb,uint8_t a)` once per destination pixel (nearest-neighbour inside stretched pieces).

## Self-review

- **Spec coverage:** container (T1), slots/9-slice/blend/icon scale (T2), loader + limits + memory (T3), fallbacks/states/NEO off/rotation (T4), lists/config/old cards/`.gts` wins/8 cap (T5), upload/validation/name safety (T6), starter NEO + slot map + import/export + plain-words validation (T7), icons (T8), docs/flash numbers (T9). Spec items left to measurement are measured in T3/T4/T7/T9.
- **Deviation from the spec to confirm:** the starter is drawn by JS in the page (`gtsDrawStarter`), not downloaded from the docs site. A phone on the GTi's own Wi-Fi has no internet, so a docs-site download would not work exactly where it is needed; one renderer also serves the slot map. The docs site only hosts the saved overlay and the README.
- **Types:** `gts::View`/`Chunk`, `skin::Atlas`/`Slot`/`SLOTS`, `skinLoad`, `skinKey`, `skinIcon`, and the four panel hooks are named identically wherever used.
