# PR #27 review briefing — "Stefan's fixes" (reinauer), against origin/main @ 8f289b4

## 1. What it is

A 12-commit series whose headline `+13184/-8132 / 39 files` overstates the review surface ~5.6x: 7370 of 13184 additions and 7270 of 8132 deletions are the regenerated gzip UI blob, duplicated into two board directories, so the authored firmware surface is ~2214 added / 862 deleted plus a 127-line UI delta. The real content is four layers: a rebuilt save path (journaled replacement in `firmware/shared/save_image.h`, a portMUX'd dirty-map snapshot/live split in `dirty_snapshot.h`+`disk_lock.h`, fail-closed interlocks via `svPrepareChange()`, geometry validation in `save_geometry.h`), a rebuilt panel→dongle transport (save/eject/status moved off ESP-NOW onto Mez's own TCP-3333 escape framing, `home_wifi.h` borrowing an existing STA association, `dongle_wifi.h` BSSID→SSID, `fleet_mdns.h` delegated alias), an HMAC-SHA256 session layer bolted alongside the existing MAC owner lock (`owner_keys.h`+`control_auth.h`), and a dongle dashboard rework with device naming, a visible Eject, Wi-Fi settings and a reviewable HTML source plus generator (`firmware/shared/webby_ui.html`, `tools/make_webby_header.py`). Two of the four save commits fix nameable data-loss bugs and the transport work solves a problem our own always-web pivot has been living with; the interlock commit and the crypto commit are not landable as written.

## 2. What is genuinely good

**fad94ad (ESP-NOW auth) — two lines that close a real hole, independent of the crypto.** Base `handleESPNOW` took only `(data,len)`: `PKT_UNPAIR` called `removeOwner(p->mac)` on the *payload* MAC with no sender check, and `PKT_DISK_EJECT` had no owner test at all. Any radio on channel 6 could evict an enrolled screen or yank the disk out from under a running Amiga. PR threads the real `src_addr` through `queuePacket` (`firmware/Gotek_XIAO/Gotek_XIAO.ino:269,391`) and adds `memcmp(source,data+1,6) || !isOwner(source)` at `:361-362` and `!isOwner(source)` at `:377`. Mez should take these regardless of what he decides about the HMAC.

**fad94ad — memory-safety fix on five screen builds.** Base `firmware/Gotek_JC3248/espnow_server.cpp:87` was `if (len < 1) return;`, then cast to `PktHello` and `_xiao_ip = String(p->ip)`. A 1-byte frame typed `PKT_PAIR_REPLY`, or a full frame with no NUL in `ip[16]`, walked the receive buffer from any sender. PR adds `len!=250` (:94), `len!=sizeof(PktHello)` (:98) and `memchr(p->ip,0,...)` (:101).

**e471d89 — the ACK could discard a USB write made during the save.** Base `doGetSave` did `memcpy(g_snap,g_dirty,mapLen)` with a comment claiming mid-transfer writes stayed dirty; they did not — the bit was in both maps and the ACK cleared it. Base also computed `crc32sw(crc,sec,...)` from the live pointer *after* writing it to the socket, so a write landing between the two discarded the whole save. `GotekDirty::begin/finish` plus a per-sector copy under `GotekDiskGuard` fixes both and is at-least-once (`finish()` merges back only `snapshot & ~live`, only on failure). Lock discipline is correct: no SD or TCP I/O inside a critical section.

**4b25e16 — a full SD card used to truncate the save *and* destroy the previous one.** Base `svPatchCore`: `while((rd=in.read(buf,16384))>0)out.write(buf,rd);` with the write result unchecked, then `SD_MMC.remove(sav); return SD_MMC.rename(tmp,sav);`. `firmware/shared/save_image.h` checks both directions per block (:48-49), verifies length twice (:53,:67), and replaces remove+rename with journal → `rename(sav,backup)` → `rename(tmp,sav)` → cleanup, with rollback at :82. Every crash window walks clean. This is also the one commit that applies alone.

**acbfd50 (geometry half) — HD save-writeback has been dead since HD flings shipped.** Base `firmware/Gotek_JC3248/espnow_server.cpp:676` was `if (mapLen > 0 && mapLen <= 256)`, admitting at most 1 MB; an HD ADF is 1802240 B → 3520 sectors → a 440-byte map, so the panel rejected the header and dropped the save silently. `GotekSaveGeometry::header/bitmap` derives the length (`((imageBytes+511)/512+7)/8` → 220 DD, 440 HD, matching the dongle's own `mapLen=(imgSecs+7)/8` exactly) and rejects set bits past EOF, closing the old path where a stray bit made the panel extend the file. Clearest single win in the PR; cherry-pickable.

**b55d663 — the plain XIAO's fling stall timer was never reset.** `firmware/Gotek_XIAO/Gotek_XIAO.ino:584` now does `received += rd; t0=millis();` inside a loop whose comment already claimed "t0 resets on every read below"; the Webby build already had it. Slow-but-steady flings aborted at 30 s total — exactly the HD/marginal-link case. Same hunk fixes the half-closed drain (`!client.connected() && !client.available()`).

**a6ad7d7 — `GotekHome` borrowing an existing STA association. Better than ours, and the missing half of our always-web pivot.** `firmware/shared/home_wifi.h:13` `borrowed = WiFi.status()==WL_CONNECTED && WiFi.SSID()==ssid;` skips both the join (:16-23) and the teardown (:34-37). Base did `WiFi.disconnect(); WiFi.mode(WIFI_AP_STA); ESP_NOW.begin();` + peer rebuild on *every* home fling — destroying precisely what our fleet console depends on (persistent STA, mDNS responder, UDP 51703 socket). Bigger: base `espnowFetchSave` had **no home path at all** (it joined `DONGLE_AP_SSID`), so save writeback over the LAN was impossible; `beginControl` makes it work. P4 even keeps its hosted C6 radio (`espnow_server_p4wifi.cpp:324`). Do not discount this because it lands on our ground.

**86cef44 — BSSID→SSID resolution is a strict fix on CYD and Waveshare_28.** (Verifier refuted my colleague's "it breaks the legacy GotekXIAO panels": nothing in the tree advertises `GotekXIAO` — only two unused constants — so before this commit `WiFi.begin("GotekXIAO",...)` could not associate with *any* dongle, and `dongle_wifi.h:9`'s bare-name fallback is the correct answer for the two non-Webby dongles that broadcast it.)

**86cef44/9356343 — `fleet_mdns.h` delegated alias.** Base renamed the device on every leadership change (`MDNS.end(); if(master) MDNS.begin(MDNS_NAME); else MDNS.begin(discoName());`), killing any open tab. PR registers the device name once at boot and only adds/removes a delegated A record. (Verifier: this is an improvement to code already in **Mez's mainline** — `doElection`, `MDNS_NAME`, `isPanel`, lowest-MAC are all at MERGEBASE and byte-identical in the PR — not a competing design. See §4.)

**86cef44 — password redaction done right.** GET emits `"WIFI_CLIENT_PASS":""` plus a separate `WIFI_CLIENT_PASS_SAVED` flag, so no mask exists that could round-trip into the stored value; the save side restores by length (`XIAO:1009`) and the no-op short-circuit folds all four fields so a name-only change still writes.

**`tools/make_webby_header.py` — the blob is auditable for the first time.** `--check` passes and regeneration reproduces both committed headers byte-for-byte; `gzip.compress(..., mtime=0)` makes it deterministic. The base tree has **no** `webui.html` and no `make_webui_header.py` anywhere, despite every base header naming that script. This should land first and separately, as a CI gate.

**Also worth keeping:** `ota_upload.h` (87 lines: `.merged.bin` rejection, `UPDATE_ERROR_NO_PARTITION`, 413 on oversize, abort on every failure, plus a 409 "save and eject the loaded disk before updating firmware"); `image_upload.h`/`guUpload`, which replaces base's memcpy into a *live mounted* volume; `GotekSave::patch/recover` for `svPatchCore`; and the module split itself, which follows the folder's conventions (`#pragma once`, purpose comment, namespaced surface — 10 of 11; `dongle_wifi.h` uses a `gotek` prefix instead) with opt-in includes that force nothing on other boards.

## 3. What is risky or wrong in this code

### Auth layer (fad94ad)

- **The authentication is opt-in by the party being authenticated.** `firmware/Gotek_JC3248/espnow_server.cpp:100` `if(p->pad[2]==1 && !GotekAuth::acceptReply(...))return;` then *unconditionally* `memcpy(_xiao_mac,p->mac,6); _xiao_ip=String(p->ip);` (:117-118) and `XIAO_IP` into CONFIG.TXT (:141). Spoof a reply with `pad[2]=0` and the screen adopts the attacker's MAC and IP as its dongle; every later fling and save-drain goes there over TCP. Same shape `Waveshare_28/espnow_server.cpp:67`, `CYD/espnow_server.cpp:140`.
- **Write-once key file, no delete path anywhere in the tree.** `owner_keys.h:47` `if(fs.exists(path))return false;`, `:77-79` trusts `reply+27` when no key is known and commits it permanently. `git grep keyPath` finds only the definition and the two uses; `wipeOwners()` (`Gotek_XIAO.ino:310`) removes only `/XIAO_CONFIG.TXT`. On JC3248 and Waveshare the screen *cannot* check the frame source even in principle (`handleIncoming(data,len)`; `onReceive` discards the peer address). One spoofed sealed `PAIR_REPLY` naming the victim dongle's AP MAC with an attacker-chosen key poisons the pairing forever; recovery is deleting a hidden dotfile from the SD card by hand. A 0-byte or partial key file is equally terminal: `loadKey` demands `size()==16` (:42), `storeKey` then refuses the existing path (:47).
- **64 sealed replies permanently brick a screen's auth.** `owner_keys.h:26-33` hands out the first free slot with no eviction; `:79-80` calls `storeKey` *before* the session lookup. 64 distinct spoofed MACs write 64 permanent files into the SD root and fill the table; no legitimate dongle can obtain a session afterwards. Table is also 16x oversize against `MAX_OWNERS 4` (`Gotek_XIAO.ino:240`), ~2.3 KB .bss.
- **Upgrade migration is silently broken.** `canEnroll` is captured at `Gotek_XIAO.ino:321` before the known-owner test, so for an already-enrolled owner without a BOOT hold it is false; `pairReply` fails at `owner_keys.h:59` and `:351` returns before the send at `:353` and the OLED line at `:355` — no frame, no display, no serial. Flash this onto a dongle that has owners and no key file and it answers every hello with silence; fixing it needs a physical BOOT hold on every dongle, stated nowhere. (Verifier: only `espnowSendUnpair` is *newly* killed — `PKT_LOCK/PKT_UNLOCK` never had a dongle handler — and dead ESP-NOW eject applies to CYD and Waveshare only, since the JC3248 family's eject was rewritten as a TCP request.)
- **CYD can never establish a session, so its eject is now a permanent no-op.** A session is created on CYD only at `CYD/espnow_server.cpp:140`, gated on `data[25]==1`. Sealed replies are produced only inside a dongle's `PKT_PAIR_HELLO` handler, and CYD never transmits a hello — its `:254` hello is a synthetic local buffer fed to `handleIncoming(fake,...)`. The `PAIR_REPLY` CYD actually receives is the dongle's unsolicited confirm burst, which is never sealed, so `acceptReply` is never called and `signCommand(_xiao_mac,...)` at `:428` always returns false. The CYD eject button silently stops working against every dongle, old or new. (Verifier-supplied; it replaces the refuted "sign key ≠ session key" mechanism, which does not exist.)
- **The commit's headline claim is false at system level.** `firmware/Gotek_XIAO_Webby/Gotek_XIAO_Webby.ino:562` still has `else if (cmd == CMD_EJECT_FORCE) doEject(client,true);` and the disk-fling path below it with no owner or token check. An unauthenticated `[FFFFFFFF][04]` from anyone on the dongle AP — or the shared LAN in always-web mode — force-ejects and drops unsaved writes. The PR hardens the transport that needs 802.11 injection and leaves the netcat-reachable one open.
- Secondary: the key travels in cleartext over unencrypted ESP-NOW and falls back to `FF:FF:FF:FF:FF:FF` when `_wavePeer->add_peer()` failed (`owner_keys.h:71`, `Gotek_XIAO.ino:352-353`, peers built with `lmk=nullptr`, nonce in the clear at offset 206); the owner is persisted and the enrol window closed 18 lines before the key is provisioned with no rollback (`:332-333` vs `:351`); `CYD`'s `data[25]` aliases its own `name[12]` field (`CYD/espnow_server.cpp:43-49`) — wire-correct today only because no dongle fills `name[]`.

### Interlocks (b55d663)

- **No escape from a save that cannot succeed.** `Gotek_JC3248.ino:3059` replaces `if(++g_sv_fail>=5){svDirtyReset(); svToast("SAVE FAILED - GAVE UP");}` with `if(++g_sv_fail>=5)g_sv_fail=0;` — the map is never discarded and `g_sv_fail` is now write-only. ## 4. Where it collides with us

**ESP-NOW auth — same concept, different transport; no technical clash, a real conceptual one.** Theirs: `/.gti-key-<mac>` (`owner_keys.h:36`) enrolled inside the ESP-NOW `PKT_PAIR_HELLO` handler during the BOOT-hold window. Ours: `CMD_ENROLL 0x07`/`CMD_AUTH 0x08`/`CMD_UNENROLL 0x09` with reject `0x05` over `TCP_CMD_ESCAPE`, tokens in `/WOWNERS.TXT` (`webby-lock-161 Gotek_XIAO_Webby.ino:93-101,:283-284`). `git grep 'pad\[[2-9]\]'` over origin/main, webby-lock-161 and panel-fleet-5923 returns nothing, so offsets 25, 26, 27-42 and the 206-249 footer are free, and the namespaces do not overlap. But merged as-is a dongle carries two owner lists, two secret stores, two enrolment windows and one BOOT gesture meaning different things per transport, and no wipe path clears the other's store (`wipeOwners` → `XIAO_CONFIG.TXT`; our `wipeWOwners` → `WOWNERS.TXT`; nothing removes `/.gti-key-*`). **Whose is better: neither alone closes the device.** Theirs adds cryptographic integrity to the transport that requires 802.11 injection; ours gates the netcat-reachable TCP write surface (`webby-lock-161:575,:601`) that theirs leaves wide open (`:562`). **Opcode 0x07 — a straight conflict, and the newcomer should move.** Theirs: bare magic `7` (`Gotek_SuperMini_Webby.ino:640`, `Gotek_XIAO_Webby.ino:563`; consumer `Gotek_JC3248/espnow_server.cpp:655`), with no `#define`, so grepping the contract does not find it — their own define block stops at `CMD_SET_NAME 0x06`. **Save/eject transport — same wire, two clients, one authenticated.** `requestOnNetwork` (`espnow_server.cpp:626-634`) writes exactly one 5-byte frame and never an `0x08` AUTH preamble; `espnowSendEject` (:639), `espnowPollStatus` (:645) and `espnowFetchSave` (:663) all use it. ## 5. The wire contract

- **`0x07`/`0x08`/`0x09` + `0x05`: broken**, by the unnamed capability probe, in both directions, as above. This is the only thing in the PR that breaks a contract Mez signed off.
- **`lk`/`lkd`/`enr` beacon flags: untouched.** Nothing in the PR touches beacon JSON keys, and their election reads `role`, which our panel emits — so fleet leadership interop holds across the merge.
- **ESP-NOW frame:** 44 bytes of footer (nonce@206, seq@214, tag@218) plus offsets 25, 26 and 27-42 are reassigned across the 10 files that include `owner_keys.h`. Nobody else claims them, so there is no clash today — but anything we add to the frame from now on must stay below offset 206, and that needs writing down.
- **Un-updated dongle or screen: every failure is silent and depends on which side was flashed first.** New screen + old dongle → `signCommand` has no session, the command is dropped locally with no diagnostic. Old screen + new dongle → unsigned frames rejected at `Gotek_XIAO.ino:377`. Upgraded dongle + already-enrolled screen → silence, no frame, no OLED, no serial, until a physical BOOT hold. There is **no capability byte in the hello**, so the dongle cannot tell an old screen from a hostile one. CYD and Waveshare lose ESP-NOW eject outright; CYD loses it against *every* dongle, updated or not.
- **TCP 3333 is reused, not replaced**, so a fling from an un-updated panel still works and an un-updated dongle still answers `0x01`/`0x02`/`0x03`/`0x04`. The one new opcode is the caps probe, so a PR panel against an un-updated dongle degrades only to "no wireless HD device" — acceptable, once it is not `0x07`.
- **Minimum to judge the crypto:** a stated new/old × screen/dongle compatibility matrix per command, a migration path for dongles that already have owners, and a hello-side capability byte. Ask for those rather than for the withheld test suite.
