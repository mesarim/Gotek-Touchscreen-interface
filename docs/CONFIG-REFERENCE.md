## WebDAV client (JC3248 / JC4827) - new in 5.9.8

The shared WebDAV client shipped wired into the JC panels in 5.9.7; **5.9.8 surfaces these keys in the `CONFIG.TXT` template** so the feature is discoverable rather than hidden. It stays off until you set `DAV=ON` and a `DAV_HOST`. HTTPS here is encrypted but **not certificate-authenticated**, and `DAV_PASS` sits in plain text on the card. Not present on the ESP32-P4 or the 7-inch boards.

| Key | Default | What it does |
|-----|---------|--------------|
| `DAV` | `OFF` | `ON` = enable the WebDAV client. `DAV_ENABLED` is accepted as the same switch (the OMEGAWARE-tree name). |
| `DAV_HOST` | (blank) | WebDAV server hostname or IP. |
| `DAV_PORT` | `443` | Server port (1-65535; anything invalid falls back to 443). |
| `DAV_HTTPS` | `ON` | `ON` = TLS (default), `OFF` = plain HTTP. |
| `DAV_USER` | (blank) | Basic-Auth username. |
| `DAV_PASS` | (blank) | Basic-Auth password. |
| `DAV_PATH` | `/` | Base path on the server. |


## Read by the firmware, not yet an active template key

These keys the firmware **honours** but its self-documenting `CONFIG.TXT` template doesn't write as an active `KEY=` line (so a fresh card doesn't switch them on for you). They work today — add the line yourself. Behaviour below is read straight from the parser. `WEBUI` and `LOG` are now surfaced as **commented hints** in the fresh-card template's "Advanced" block, so upgraders can discover them without the template turning them on. The `WEBUI` / `LOG` / `WIFI_CLIENT_*` rows are the JC3248 / JC4827 web-panel extras; the ESP32-P4 build reads only `SS_IDLE` and `SS_LOAD` from this group. The WebDAV (`DAV_*`) keys are now written into the JC template as of 5.9.8 (see the WebDAV section above); only `DAV_TEST`, a boot smoke-test, stays out.

| Key | Default | What it does |
|-----|---------|--------------|
| `WEBUI` | `OFF` | `ON` = serve the shared web panel over home WiFi (needs `HOME_SSID`/`HOME_PASS` + `LINK=HOMEWIFI`). **Now a commented hint in the template.** |
| `LOG` | `ON` | `OFF` = disable the `/gti.log` diagnostic log (on by default). **Now a commented hint in the template.** |
| `DAV_TEST` | `—` | Smoke test — fetch this one remote path once at boot to prove the wiring. |
| `SS_IDLE` | `—` | Seconds of idle before the screensaver starts (overrides the built-in default). Fine-tuning; intentionally kept out of the template. |
| `SS_LOAD` | `—` | Seconds the load screen lingers before the screensaver may take over. Fine-tuning; intentionally kept out of the template. |
| `WIFI_CLIENT_SSID` | `—` | Alias of `HOME_SSID` (OMEGAWARE-tree name; empty never erases a value set by the other key). |
| `WIFI_CLIENT_PASS` | `—` | Alias of `HOME_PASS` (OMEGAWARE-tree name). |


## Per-dongle keys — `DONGLE_<MAC>`

These are written by the screen, not by you: **SCAN DONGLES → RENAME / LOCK** puts them in
`CONFIG.TXT`, keyed by the dongle's MAC with the colons stripped and the letters in capitals
(`A0:F2:62:EC:8B:80` becomes `DONGLE_A0F262EC8B80`). They are listed here so a card you are
reading by hand makes sense, and so you can delete a stale one.

| Key | Default | What it does |
|-----|---------|--------------|
| `DONGLE_<MAC>` | (blank) | The friendly name you gave that dongle (**RENAME** in SCAN DONGLES). |
| `DONGLE_<MAC>.LOCK` | `0` | `1` = this dongle is **locked to this screen** over ESP-NOW (the **LOCK** button). See `PAIRING.md`. |
| `DONGLE_HOME_IP` | (blank) | Cached home-network IP of the dongle — a fallback for when mDNS is slow. Auto-filled. |

## Fleet over home WiFi + the WiFi owner-lock

> **Not in a release build yet.** These keys arrive with the branches `panel-fleet-alwaysweb`
> (screen) and `webby-lock-161` (dongles). A 5.9.23 card neither writes nor reads them; they are
> documented here so the two trees agree on the names before they harden.

| Key | Default | What it does |
|-----|---------|--------------|
| `MDNS_NAME` | `gotekomega` | This screen's own mDNS name, so it answers at `<name>.local`. A screen is always the fleet leader, so with two screens on one network the lower-MAC one keeps `gotekomega.local` and the other falls back to `gotekomega-<mac>.local`. Set this and the screen never contends at all. |
| `PANEL_TOKEN` | (generated) | This screen's 32-hex-character owner identity, made once on first boot. It is what a dongle stores when you **CLAIM** it. **Don't hand-edit and don't copy it to a second card** — two screens sharing a token are one owner as far as every dongle is concerned. Delete the line to become a new owner (and re-claim your dongles). |
| `DONGLE_<MAC>.MINE` | `0` | `1` = this screen has claimed that dongle over WiFi. Purely the screen's own memory of it; the dongle keeps the authoritative list. Lose it and the dongle disappears from your fleet view — **INFO → RELEASE LOCKS** is the way back. |

### `NETWORKS.TXT` — remembered WiFi networks

Not a `CONFIG.TXT` key but a second file in the root of the same card. The screen keeps up to
**8** networks here, most-recently-used first, and at boot (or after a dropped link) joins the
strongest one it recognises — so a screen just works at home, then at the club, then at a
friend's, without a reconfiguration each time. `HOME_SSID` / `HOME_PASS` are migrated in as the
first entry the first time the file is written, and stay in step with whatever you are on now.

Each line is the SSID, a **tab**, then the password (a network with no password just ends
after the tab); lines starting with `#` are ignored, so the file explains itself:

```
# Remembered WiFi networks: SSID<TAB>password, most-recent first (max 8). Edit or delete lines to forget.
my-home-wifi	hunter2
clubday-guest
```

Manage it from **INFO → SAVED WIFI** (view, and forget one). Deleting the file forgets every
network; the screen falls back to `HOME_SSID`.

## What a Webby dongle stores (LittleFS, not the SD card)

A Super Mini / XIAO dongle has no card — it keeps its settings in its own flash. You cannot
edit these by hand; they are here so you know what a wipe actually wipes.

| File | Holds | Cleared by |
|------|-------|-----------|
| `/WEBBY.TXT` | `SSID=` / `PASS=` / `MODE=` / `NAME=` — the home WiFi it joins, whether it is in WiFi or ESP-NOW mode, and its fleet name | BOOT held 10 s |
| `/APCFG.TXT` | `APNAME=` / `APPASS=` — the custom name and WPA2 password of the dongle's **own** setup access point | not cleared by a WiFi wipe (deliberate: the AP stays protected) |
| `/WOWNERS.TXT` | `OWNER=<32 hex>` per screen that has claimed it, up to **4** — the WiFi owner-lock | UNCLAIM from the owning screen, or BOOT held 10 s |
| `/XIAO_CONFIG.TXT` | the MAC addresses of up to **4** ESP-NOW owners (the older lock, see `PAIRING.md`) | BOOT held 15 s in ESP-NOW mode |
| `/THEME.TXT` | the theme its web page uses | reflashing |
