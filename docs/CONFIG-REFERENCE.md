## WebDAV client (JC3248 / JC4827) - new in 5.9.8

The shared WebDAV client shipped wired into the JC panels in 5.9.7; **5.9.8 surfaces these keys in the `CONFIG.TXT` template** so the feature is discoverable rather than hidden. It stays off until you set `DAV=ON` and a `DAV_HOST`. HTTPS here is encrypted but **not certificate-authenticated**, and `DAV_PASS` sits in plain text on the card. Not present on the ESP32-P4 or the 7-inch boards.

| Key | Default | What it does |
|-----|---------|--------------|
| `DAV` | `OFF` | `ON` = enable the WebDAV client. `DAV_ENABLED` is accepted as the same switch (the OMEGAWARE-tree name). |
| `DAV_HOST` | (blank) | WebDAV server hostname or IP. |
| `DAV_PORT` | `443` | Server port (1-65535; anything invalid falls back to 443). |
| `DAV_HTTPS` | `ON` | `ON` = TLS (default), `OFF` = plain HTTP. |
| `DAV_USER` | (blank) | Basic-Auth username. |
| `DAV_PASS` | (blank) | Basic-Auth password. |
| `DAV_PATH` | `/` | Base path on the server. |


## Read by the firmware, not yet an active template key

These keys the firmware **honours** but its self-documenting `CONFIG.TXT` template doesn't write as an active `KEY=` line (so a fresh card doesn't switch them on for you). They work today — add the line yourself. Behaviour below is read straight from the parser. `WEBUI` and `LOG` are now surfaced as **commented hints** in the fresh-card template's "Advanced" block, so upgraders can discover them without the template turning them on. The `WEBUI` / `LOG` / `WIFI_CLIENT_*` rows are the JC3248 / JC4827 web-panel extras; the ESP32-P4 build reads only `SS_IDLE` and `SS_LOAD` from this group. The WebDAV (`DAV_*`) keys are now written into the JC template as of 5.9.8 (see the WebDAV section above); only `DAV_TEST`, a boot smoke-test, stays out.

| Key | Default | What it does |
|-----|---------|--------------|
| `WEBUI` | `OFF` | `ON` = serve the shared web panel over home WiFi (needs `HOME_SSID`/`HOME_PASS` + `LINK=HOMEWIFI`). **Now a commented hint in the template.** |
| `LOG` | `ON` | `OFF` = disable the `/gti.log` diagnostic log (on by default). **Now a commented hint in the template.** |
| `DAV_TEST` | `—` | Smoke test — fetch this one remote path once at boot to prove the wiring. |
| `SS_IDLE` | `—` | Seconds of idle before the screensaver starts (overrides the built-in default). Fine-tuning; intentionally kept out of the template. |
| `SS_LOAD` | `—` | Seconds the load screen lingers before the screensaver may take over. Fine-tuning; intentionally kept out of the template. |
| `WIFI_CLIENT_SSID` | `—` | Alias of `HOME_SSID` (OMEGAWARE-tree name; empty never erases a value set by the other key). |
| `WIFI_CLIENT_PASS` | `—` | Alias of `HOME_PASS` (OMEGAWARE-tree name). |

## Custom cracktros

Put your own cracktros on the SD card as `/cracktro/<name>.gti` and select one with
`CRACKTRO=<name>`, or let the panel pick a random one with `CRACKTRO=CUSTOM`.

A `.gti` is a plain text file: a short list of **patterns**, each one a built-in effect
plus your own title, subtitle, colour and optional 1bpp logo. The shape is borrowed from
the 1991 RSI Demomaker, where a demo was also a handful of "patterns" bolted together.

```ini
GTICRACK 1
NAME=Omegaware
AUTHOR=Dimmy

[PATTERN]
FX=COPPER
TIME=4000
TITLE=OMEGAWARE
SUB=* MEZ & DIMMY *
COL=FFE000
SCROLL=ON

[SCROLL]
TEXT=OMEGAWARE PRESENTS ... YOUR OWN CRACKTRO, LOADED FROM SD ...
```

| key | meaning |
| --- | --- |
| `GTICRACK 1` | Must be the first real line. Files without it are rejected. |
| `NAME` / `AUTHOR` | Free text, for your own reference. |
| `[PATTERN]` | One segment of the cracktro. Up to 4 per file, shown in order and then looped. |
| `FX=` | `COPPER`, `STARFIELD`, `RASTER`, `PLASMA`, `BOING`, `SYNTH` or `LOGO`. |
| `TIME=` | How long this pattern is shown, in milliseconds (default 4000). |
| `TITLE=` / `SUB=` | Your own text. Leave one out and the effect keeps its built-in line. |
| `COL=` | `RRGGBB` hex. The panel is RGB565, so very close shades may land on the same colour. |
| `SCROLL=ON` | Show the scroller under this pattern. `OFF` hides it. |
| `LOGO=n` | Draw `[LOGO n]` instead of `TITLE` (use with `FX=LOGO`). |
| `[SCROLL] TEXT=` | The scrolling message, shared by every pattern in the file. |
| `[LOGO n]` | `W=` and `H=`, then rows of hex: **1bpp, MSB-first, row-major**. |

**Limits:** 32 KB per file, 4 patterns, 2 logos, logo max 128×48, scrolltext 512 characters.

**If anything is wrong** — folder missing, file missing, bad first line, a logo over the
limit — the panel quietly falls back to the built-in cracktro. It will never show a blank
screen. Plug in USB serial to see the reason, e.g.
`[gti] /cracktro/omega.gti: missing GTICRACK magic`.

**Built-in names win.** `CRACKTRO=DENISE` is the built-in Denise theme even if you also
have a `/cracktro/denise.gti`. Give your own file a different name to select it.

Ready-made examples live in [`docs/examples/cracktro/`](examples/cracktro/).

With `SSMODE=CRACKTRO` the same cracktro runs as the screensaver, looping until you touch
the screen. That mode brings its own content, so it works with no `/screensaver` folder.
